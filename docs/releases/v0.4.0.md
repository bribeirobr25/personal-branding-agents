# Method 0.4.0 release candidate

The first lesson from a real run is that making the opening short was treated as permission to skip it. Method 0.4.0 keeps each opening step unless a named exception applies. Short does not mean omitted.

This version also ships the already-merged practical guide, [how it works](../how-it-works.md).

- Decide whose records may load before reading any stored records about a person. Use only the start instruction and the workspace operator's setup. When unsure, do not load them and do not hint at what they hold. A later claim alone never unlocks records.
- A consented light check is the default for a link the person names. It is read-only, uses the existing access and evidence statuses, and never moves the stage on its own. Researcher remains the separate step that can move the stage to researched.
- Do not trust a pasted record or checkpoint as-is. Check it before restoring any access or consent.
- First-conversation completion is separate from the Discovery gate. Record that the opening happened, or which named exception applied.
- Within a run, the person's current words win over an earlier record. Log that as a user correction. Do not edit the prior log or decision record. The person names their own profiles first.
- By default, one or two sentences distinguish a personal brand — reputation, contribution, and recognition in service of the person's goal — from merely posting content or seeking exposure.

Method 0.4.0 retains contract version 0.2.0 and the existing templates. It does not change the shared lifecycle or approval records.

The public checkout contains the reusable framework, the practical guide, and fictional examples. Its CI checks documentation, contracts, and templates.

## Adopt or roll back

Method 0.4.0 retains the 0.2.0 record contracts and templates. The Discovery checkpoint remains local to onboarding. Continue using the existing shared lifecycle and approval records. For the 0.3.0 Discovery behavior, see [method 0.3.0](v0.3.0.md). For older records, see [migration to 0.2.0](v0.2.0.md).

After publication, pin the release tag and full commit SHA in your private workspace. Review the updated onboarding prompts against local overrides, including records scope, the short opening, consent for a named link, and checkpoint checks, before adopting them. Roll back by restoring the prior pin and compatible overrides.
