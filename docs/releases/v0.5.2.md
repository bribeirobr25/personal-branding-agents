# Method 0.5.2 release candidate

These Discovery wording fixes follow method 0.5.1. Method 0.5.2 keeps the two-part Discovery gate, `validated_for_strategy`, and the rule that a correction and a closed gate do not share a reply. De-duplication of repeated rules is deferred to 0.6. This note is Discovery only. It does not change positioning.

- **Host memory and this conversation.** Host memory, notes, and earlier chats with the same assistant count as stored records, not as something said in this conversation. This conversation starts at the opening, or at the start instruction. Always ask how to address the person, even if an earlier chat used a name.
- **Order of the ask-once questions.** Ask the consent question in the first reply after a third party's material appears. In the summary reply, the proof-points ask is one optional line, and the validation question comes last as the only real question. Do not stack consent, proof points, and validation in one reply.
- **Closing Discovery.** A short worked example uses a fictional person called Alex and example.com. The confirmed profile separates what sources showed from what the person said. Each held-out item, including each mismatch, says what would resolve it. Never mention a held-out item in a direction, even conditionally. The final question always includes an "or stop here" option. If the person answers "a mix", ask which part to explore first.
- **Reading guide.** A host's own platform tool that reads only public data from a page or account the person named, with no sign-in of theirs, counts as step 1. Name the tool type in the access list. Anything that uses the person's own account is step 2. Tool types only.
- **Own-material mismatches.** For a mismatch inside the person's own CVs, site, or profiles, what resolves it is usually their one-line answer. Say so, and keep the claim held out until then.
- **Gate alignment.** Name the held-out items and say the gate can close with them held out, never that nothing blocks. Record `validated_for_strategy` only when both gate conditions hold.

Method 0.5.2 retains contract version 0.2.0 and the existing templates. It does not change the shared lifecycle or approval records. De-duplication is deferred to 0.6.

The public checkout contains the reusable framework, the practical guide, and fictional examples. Its CI checks documentation, contracts, and templates.

## Adopt or roll back

Method 0.5.2 retains the 0.2.0 record contracts and templates. The Discovery checkpoint remains local to onboarding and is kept in the conversation. Continue using the existing shared lifecycle and approval records. For the 0.5.1 Discovery behavior, see [method 0.5.1](v0.5.1.md). For older records, see [migration to 0.2.0](v0.2.0.md).

After publication, pin the release tag and full commit SHA in your private workspace. Review the updated Discovery prompts against local overrides before adopting them. Roll back by restoring the prior pin and compatible overrides.
