# Method 0.5.3 release candidate

These optional Discovery asks follow method 0.5.2. Method 0.5.3 keeps the two-part Discovery gate, `validated_for_strategy`, and the rule that a correction and a closed gate do not share a reply. De-duplication of repeated rules is deferred to 0.6. This note is Discovery only. It does not change positioning. It does not add a phase, a gate, or an agent.

- **Existing public presence.** When summarizing the person's existing public presence, from the public-presence read or a connected read, add one tentative sentence on what that presence connects the person with today, and let them say keep, refresh, or move away. Ask once. In Closing Discovery, a direction may be labelled refresh or change of direction. Use a label only when the confirmed profile supports it. There is no fixed count, and a direction does not need a label.
- **A "never" statement.** When the person says they will never do something, ask once whether that is a lasting conviction or a current feeling, only if that is still unclear after the clarification of what they do not want to be, so it is not a second question, and record which as `user_reported`, not as verified.
- **What people already ask them for help with.** An optional question, asked once, not in the summary reply. Record the answer as `user_reported`. Paraphrased by default with no names; a third party's verbatim words only with that person's consent, and never in a public file or example.
- **A story told as proof.** When the person tells a story as proof, ask once what made it work there and where it might not work.
- **A goal that sounds like a mission.** Ask once about the person's own outcome. Do not put that ask in the first message.

Each ask is optional, happens once, has no fixed count, and is not a gate. Do not stack these asks with consent, proof points, validation, or the future-self question. At most one of these asks per reply; the rest wait or are skipped. Examples, where the workflow uses them, use the synthetic person Alex and example.com only.

Method 0.5.3 retains contract version 0.2.0 and the existing templates. It does not change the shared lifecycle or approval records. De-duplication is deferred to 0.6.

The public checkout contains the reusable framework, the practical guide, and fictional examples. Its CI checks documentation, contracts, and templates.

## Adopt or roll back

Method 0.5.3 retains the 0.2.0 record contracts and templates. The Discovery checkpoint remains local to onboarding and is kept in the conversation. Continue using the existing shared lifecycle and approval records. For the 0.5.2 Discovery behavior, see [method 0.5.2](v0.5.2.md). For older records, see [migration to 0.2.0](v0.2.0.md).

After publication, pin the release tag and full commit SHA in your private workspace. Review the updated Discovery prompts against local overrides before adopting them. Roll back by restoring the prior pin and compatible overrides.
